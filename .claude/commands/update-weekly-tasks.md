# 更新进度追踪页面

用户提供本周的目标和计划后，按照「每日最新进度追踪」页面的现有模板更新内容。

**页面 ID**: `364bb9e3-b84d-809b-bc5d-c65b0574bfe6`

## 页面结构（模板）

页面从上到下由以下模块组成，更新时保持这个结构不变：

```
# 数据追踪
📅 追踪周期 callout
---
# 大家写计划&记录时请附上具体数据📊
## 📊 任务总览 {toggle}          ← 看板视图，不动
---
## 渠道板块 × N {toggle}         ← 每个渠道一个，内含三列+任务追踪视图
---
数据库（勿删）                    ← 不动
---
# 每日任务清单 {toggle}           ← 可收起，按日期→按人头分组的 checkbox
```

## 渠道板块列表（从页面动态读取，以下为当前状态参考）

每个板块格式：`## 渠道名 @负责人 {toggle="true"}`，内含：
- 三列布局（目标 / 计划 / 进展），各自为 `<details>` toggle
- 一个链接数据库视图（按渠道筛选的任务追踪）

当前渠道：

- 推特官号、领英官号、公众号
- 6.14 corgi 线下活动
- Reddit、Community-Led Growth

**重要**: 渠道和负责人以页面实际内容为准，不要硬编码。每次执行时先 fetch 页面读取最新状态。

## 执行流程

### 1. 读取当前页面
- Fetch 页面，提取所有渠道板块、负责人、现有计划内容

### 2. 接收用户输入
- 用户会告诉你本周各渠道的目标和计划
- 可能是全部渠道，也可能只更新部分渠道

### 3. 更新渠道板块
- 把用户提供的目标写入对应渠道的「目标」toggle
- 把用户提供的计划写入对应渠道的「计划」toggle
- 用户没提到的渠道保持原样不动
- 「进展」toggle 不动（由团队成员自己更新）
- 任务追踪视图不动

### 4. 更新追踪周期
- 如果用户指定了新的追踪周期，更新 callout 中的日期

### 5. 生成每日任务清单
- 用 `date` 命令验证每个日期的实际星期几
- 默认范围：本周工作日到周六，周日不列（用户指定则以用户为准）
- 标题：`# 每日任务清单（M.DD-M.DD）{toggle="true"}`
- 每天一个 toggle：`### M.DD 周X {toggle="true"}`
- 每天内按负责人分组，任务从该人负责的所有渠道计划中提取

#### 任务生成规则
- 严格按渠道归属分配，不交叉
- 数字和描述必须与计划一致（计划写50位就是50位）
- 「每日」→ 每天列
- 「每周一」→ 范围内的周一；没有周一则放第一天
- 「每周X」→ 放对应的星期
- 「周数据」→ 放周五
- 计划为空/placeholder → 一条通用任务「XX渠道推进」
- 人与人之间用 `<empty-block/>` 分隔

### 6. 更新页面
- 用 `update_content` 精确替换需要更新的部分
- 不触碰：任务总览视图、各渠道的任务追踪视图、数据库（勿删）、进展内容
- 每日任务清单区域整体替换

### 7. 完成后汇报
- 列出更新了哪些渠道的目标/计划
- 列出每日任务清单的日期范围和对应星期
- 列出每个人的渠道和每日任务数
- 提醒哪些渠道计划仍为空
